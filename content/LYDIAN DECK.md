# CRYPTOGRAPHIC HITCHING

To weave collaborative annotations into an immutable provenance chain without breaking your local-first, peer-to-peer guarantees, the Lydian Deck uses a pattern called **Cryptographic Hitching**.

Because a module’s `mTess` provenance strata are completely immutable (you can’t alter history), the annotations cannot be inserted directly _into_ the provenance data blocks. Instead, they exist in a parallel, highly mutable **Session CRDT Overlay** that hitches individual notes to specific cryptographic hashes.

Here is exactly how a Guild Master leaves a contextual note live, and how the underlying CRDT engine synchronizes it across the local mesh network in milliseconds.

## THE UX: DROPPING A "SCRIBE'S MARK"

When a Guild Master unzips an `mTess` block in the Metadata Column, every individual layer—whether it’s the Genesis Author DID or a down-chain Mutation Hash—acts as a distinct anchor point.

1. **The Hover Trigger:** As the Master hovers over a specific stratum block (e.g., a signature hash), a minimal edit icon appears—the **"Scribe’s Mark"**.
    
2. **Inline Fracture:** Clicking it doesn't open a pop-up window. It causes the specific layer block to fracture slightly downward, sliding open an inline, markdown-ready text area directly attached to that block.
    
3. **Presence Indicators:** The borders of the note match the Master's unique profile color. If another Master is looking at the same block, they see a faint colored dot next to that layer, signaling that a peer is actively drafting an annotation there.
    

## THE DATA SCHEMA: ANCHORING TO THE HASH

## THE CRDT SYNCHRONIZATION LIFECYCLE

When a Guild Master types a single character into an annotation box, the local-first mesh orchestrates a real-time sync cycle through Tauri's IPC boundary to the local network layer.

**1.Local State Capture:**Sub-1ms.

As Master Lewis types, the React frontend captures the keystrokes and applies them to a local instance of the CRDT text object (e.g., `Y.Text`). The local UI updates instantly with no network round-trip delay.

**2.Tauri IPC Delta Encoding:**Sub-5ms.

The Tauri application bridge detects the document modification event. It compiles the raw character insertion into a tiny, lightweight binary delta packet (a state vector update) and pushes it from the frontend Webview down to the Rust core actor.

**3.Gossipsub Mesh Broadcast:**~10-30ms (LAN).

The Rust core receives the binary update and wraps it in a libp2p `Gossipsub` message tagged with the active session ID. It broadcasts this packet over the local Wi-Fi / WebRTC mesh network directly to the other active Guild Masters' nodes.

**4.Remote Integration & Dom Merge:**~5ms upon receipt.

The peer nodes receive the binary delta via their background libp2p threads, pass it up their respective Tauri IPC channels, and feed it into their local frontend CRDT engines. The document mathematically resolves and merges the text streams.

**5.Presence Rendering:**Instantaneous.

The Lydian Decks of the other Masters render the text updates in real-time. A tiny colored remote cursor tracks exactly where Master Lewis is typing, updating fluidly as his thoughts take shape on the unzipped layer.

## RESOLVING COLLABORATIVE COLLISIONS

Because two Guild Masters might decide to annotate the exact same provenance block at the exact same moment, the CRDT structure handles conflicts gracefully without requiring a central server or database lock:

> **Concurrent Edits Rule:** If Master A and Master B click the same layer block simultaneously, the CRDT treats the `annotations["0x9f8e7d6c..."]` key as a collaborative **Array**. Instead of overwriting each other, the system simply creates two independent, clean annotation cards stacked sequentially beneath that block, grouped clearly by each Master's DID profile.

When the final **Sovereign Stamp** is struck to approve the _Tesserae_, these session annotations are compiled alongside the credential. The learner gets a clean record of exactly what feedback was appended to which piece of code or artifact history.
